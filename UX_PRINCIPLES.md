# UX principles

## Working surfaces, not decorative metrics

Cohort Control presents exceptions and a compact context strip. The lifecycle filters operational records rather than decorating the header. Admissions is a dense table or horizontal stage board. Participant readiness is a register with checklists in an inspector. The brief uses an editorial paper layout. Each surface fits its operator question.

## Identity

Light warm working paper, sage navigation, ink type and restrained rust priority communicate a calm operating environment. Manrope headings and DM Sans text are bundled locally. Small corner radii and fine dividers give hierarchy without stacks of identical cards. Colour accompanies explicit words and icons; state never depends on colour alone.

## Context and feedback

Record inspectors preserve the current workspace. Every transaction gives feedback and an audit trail. Readiness and queue removal respond immediately. Reversible completion can be toggled. Room conflict attempts return an explanation instead of writing invalid state. Reminder drafts are idempotent and labeled as unsent. Empty states explain how to return to records.

## Keyboard and responsive behavior

Native buttons/selects/checkboxes, semantic tables, visible focus, a skip link and Radix modal focus containment are used. Ctrl+K / ⌘K opens commands; arrows and Enter choose commands; Escape closes dialogs. Search shortcut `/` excludes form controls. Desktop uses dense working tables; tablet places contextual blocks below the queue; mobile collapses navigation and scrolls tables within their boundaries. A named icon button keeps the command palette accessible on mobile. Dialogs respect reduced motion.

## Deliberate constraints

No simulated chatbot, AI-insights card, candidate score, decorative chart or marketing hero. No drag-and-drop admission decisions; the inspector gives a deliberate stage control and human confirmation for offer/acceptance. Snapshot memo text is not a competing source of truth: the visible brief always recomputes.

Accessibility checks combine DOM semantics, keyboard/browser journeys and automated contrast analysis; automation does not replace assistive-technology review. System-scale changes, real-screen-reader evaluation and additional browsers remain production hardening work.
